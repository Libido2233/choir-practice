# 识谱与校对

## 输入与依赖

优先利用已校正的 MusicXML/MXL 或结构化数据。MXL 是压缩包，按 `META-INF/container.xml` 指定的主文件读取；不要误读元数据 XML。解析 MusicXML 时处理命名空间、divisions、backup/forward、chord、voice、staff 和 grace。

PDF/图片可用本地 Audiveris 得到 MusicXML 初稿，再按原谱核对。矢量 PDF 的字形位置可辅助修正，但音乐字体、谱线间距和声部顺序都须从当前谱确认。扫描件需先检查倾斜、裁切和清晰度。从当前谱确定音符位置、小节数、拍号与声部顺序。

先检查当前 Python 中可用的 PDF 库和本地识谱工具，按已安装能力选实现。生成练习 HTML 的脚本只用 Python 标准库；PDF 提取和识谱依赖独立准备。Audiveris 项目：https://github.com/Audiveris/audiveris 。Skill 不附带其程序，分享时按其许可处理。识谱进程退出成功后仍需确认 MusicXML/MXL 可解析、声部与小节完整；日志中的保存失败不能只看退出码判断。

## 音高与节奏

- 实际音高、谱面音高、唱名分别保存。结合 MusicXML 的音高、transpose 和谱号语义，对照原谱及已知音判断，避免把八度移调重复执行。男高音高音谱号下的 8 常表示比视觉读谱低八度发声；不得由“T”名称推断所有谱均如此。
- 固定唱名以 C4 对应无点 1：E3 是下点 3，D♭4 是 ♭2。首调唱名则随主音而变；两者切换不改变声音。不要用唱名或听觉明亮程度猜测八度。
- 按声部、音高和连续时序合并延音线用于播放；乐句连线保留各音的起音。跨小节、跨行延音保持实际音高，处理临时升降号随延音延续的情况；其后的独立音按新小节记号处理。备选音与实际合唱分部要区分，避免误当和弦齐奏。声部内独立旋律分别累计时序；验证每条旋律的休止、三连音与延音，不用整小节总长代替分部校对。
- 用有理数或足够精度累计 divisions。小节拍长按当前拍号计算，弱起以实际长度计；休止、连音组、附点和变拍分别处理。各声部共享同一全局拍轴，声部间空白用休止补齐，不通过挪动音符消除识谱错误。
- 明确反复、跳房子和 D.C./D.S./Coda 的播放顺序。必要时展开到数据中，同时保留原小节标签。固定速度练习可简化渐慢与延长处理；在交付时说明影响排练的差异。
- 打击乐单独作为轨道处理。识谱所得 `<unpitched>` 不是钢琴音高，按谱中打击乐映射生成节奏数据。

## 谱面与简谱

歌词采用音符关联的结构化文字，优先读取 MusicXML 的 `lyric/text`、`syllabic`、`extend` 和歌词段号。矢量 PDF 提取实际文字，按声部归属与音符位置配对；扫描谱用识别文字并人工核对。保留标点，检查一个音对应多个字符或多段歌词，避免重叠。空白段落不补写。

可沿用原谱的五线谱图形，但先去掉截图里的歌词，由文字数据单独排版；同时保留谱号、八度标记、和弦、表情和连线。优先过滤原 PDF 的歌词绘制操作，避免白色遮盖破坏重叠的曲线。按当前谱确认文字字体与字号，PDF 文字位置同时处理绝对定位 Tm 和相对位移 Td/TD；不可直接套用另一首歌的字体或坐标。裁图高度包含贝塞尔控制点和谱号下沿，再裁掉空白。逐部核对歌词归属、延长端点及有词/无词段落，导出 MusicXML 时保留歌词关联。

区分原谱明确休止和该声部未列出：后者标为 sourceAbsent，显示缺谱提示，不能自动补写主旋律或将占位休止作为原谱事实。

按全局行号对齐各声部：同一 `systems` 项中给每个声部放这一行的五线谱与简谱。不同声部有独立分页时，重新按小节范围切片，不按图片序号硬配。

简谱应与每个音和休止的原谱横坐标对应；长音增时线、休止 0、附点、减时线、八度点、三连音和连线均按实际时值与记号绘制。一个声部有多条独立旋律时，用上下两排或分部表示。无法明确表达的结构保留原谱并校对，不省略后宣称完整简谱。

原有项目已有原谱切片和简谱生成器时优先复用；只将其通用逻辑提取到新项目。通用播放器接收已渲染的图/SVG，不替代记谱排版引擎。

## 最小核验

逐部核对小节数、音域、各小节时值和声部入口；抽听起始音、休止后重入、调号改变、最高最低音和跨行延音。对异常小节回看原谱，保存修正。多个声部一起试听验证对齐。未逐部校对时输出“待校对”草稿，用户要求全团成品时继续完成其余声部。
